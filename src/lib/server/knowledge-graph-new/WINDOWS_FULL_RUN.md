# Knowledge Graph: Full Run on a New Windows Laptop

This guide starts with a clean Windows laptop, clones the repository from
GitHub, prepares the local runtimes, obtains document chunks, runs a small
benchmark, runs the full Knowledge Graph build, and inspects the result.

The Knowledge Graph is backend-only. It does not need or add UI integration.

## Before moving to the laptop

The current repository and branch are:

```text
https://github.com/MAP9900/Deployable-Knowledge.git
kg-clean
```

The Knowledge Graph changes must be committed and pushed to that branch before
the Windows laptop clones it. If the changes are later merged, replace
`kg-clean` below with the destination branch.

`app.db` is intentionally ignored by Git. A fresh clone therefore will not
contain the document or its chunks. Choose one of these approaches:

1. Re-ingest the document on the Windows laptop.
2. Close the application on the original laptop and copy `app.db`, plus
   `app.db-wal` and `app.db-shm` if they exist, into the cloned repository root.

Copying the database also preserves any Knowledge Graph stage caches already
stored in it.

## 1. Install the prerequisites

Install:

- Git for Windows: <https://git-scm.com/download/win>
- 64-bit Python 3.11: <https://www.python.org/downloads/windows/>
- Node.js 22 LTS: <https://nodejs.org/en/download>
- Ollama for Windows: <https://ollama.com/download/windows>

Node must be at least `22.12.0` for this repository's Vite version. During the
Python installation, enable **Add Python to PATH** and install the Python
launcher.

Ollama supports native Windows NVIDIA and AMD acceleration. Install the current
GPU driver before continuing:

- NVIDIA: <https://www.nvidia.com/download/index.aspx>
- AMD: <https://www.amd.com/en/support>

Open a new PowerShell window after the installations and verify:

```powershell
git --version
node --version
npm --version
py -3.11 --version
ollama --version
```

## 2. Clone the repository

Choose a working directory and run:

```powershell
Set-Location $HOME

$RepoUrl = "https://github.com/MAP9900/Deployable-Knowledge.git"
$Branch = "kg-clean"

git clone --branch $Branch $RepoUrl
Set-Location .\Deployable-Knowledge
git status
```

For a private repository, authenticate with GitHub when Git prompts. Confirm
that this guide exists in the clone:

```powershell
Test-Path .\src\lib\server\knowledge-graph-new\WINDOWS_FULL_RUN.md
```

The command must return `True`.

## 3. Install the Node dependencies

From the repository root:

```powershell
npm install
npm run check
```

The existing unused `.profile-empty` CSS warning is unrelated to the Knowledge
Graph. The check should otherwise report zero errors.

## 4. Create the Python environment

Create the project-local environment:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
```

The backend automatically detects `.venv\Scripts\python.exe`; no
machine-specific path is stored in the code.

### Optional: install GPU-enabled PyTorch first

For an NVIDIA laptop, use the command generated by the official PyTorch
selector:

<https://pytorch.org/get-started/locally/>

Select:

```text
Stable / Windows / Pip / Python / the CUDA version supported by the laptop
```

Run its generated command with the virtual environment active, or replace its
leading `pip` with:

```powershell
.\.venv\Scripts\python.exe -m pip
```

This step is separate because the correct PyTorch build depends on that
laptop's GPU driver and CUDA support. For CPU-only execution, skip it.

Install the pinned GLiNER code:

```powershell
.\.venv\Scripts\python.exe -m pip install `
  -r .\src\lib\server\knowledge-graph-new\requirements.txt
```

Verify the required joint relation-extraction API:

```powershell
.\.venv\Scripts\python.exe -c "import os; os.environ['USE_TF']='0'; import pyarrow as pa; pa.PyExtensionType=getattr(pa,'PyExtensionType',pa.ExtensionType); from gliner import GLiNER; assert hasattr(GLiNER,'inference'); print('GLiNER relation API ready')"
```

## 5. Download and verify Gemma

The implementation expects the exact Ollama tag below:

```powershell
ollama pull gemma4:12b
ollama list
```

Confirm that `gemma4:12b` appears in the list. Ollama normally runs in the
background and exposes `http://localhost:11434`.

If `ollama pull` says that the tag does not exist, stop here and verify the
intended tag before changing the implementation or substituting another model.

## 6. Put document chunks in `app.db`

The database must be named `app.db` and be located in the repository root.

### Option A: copy the existing database

Close the application on both laptops. Copy these files from the original
repository root when present:

```text
app.db
app.db-wal
app.db-shm
```

Place them beside `package.json` in the Windows clone.

### Option B: ingest on Windows

Start the application:

```powershell
npm run dev
```

Open the local URL printed by Vite, ingest the document, and wait for ingestion
to finish. Stop the development server with `Ctrl+C` before starting the
Knowledge Graph run.

## 7. Find the document ID

This command uses the repository's database client, so a separate SQLite
installation is not required:

```powershell
$ListDocuments = @'
import { databaseClient } from "./src/lib/server/database/database.ts";

const result = await databaseClient.execute(`
  SELECT d.id, d.title, COUNT(c.id) AS chunks
  FROM documents d
  LEFT JOIN document_chunks c ON c.document_id = d.id
  GROUP BY d.id, d.title
  ORDER BY d.title
`);

console.table(result.rows);
'@

node --import tsx --input-type=module -e $ListDocuments
```

Copy the desired document ID:

```powershell
$env:KG_DOCUMENT_ID = "PASTE_DOCUMENT_ID_HERE"
```

Do not continue if its chunk count is zero.

## 8. Define the reusable build command

Run this once in the current PowerShell session:

```powershell
$RunKnowledgeGraph = @'
import { writeFile } from "node:fs/promises";
import { buildKnowledgeGraph } from "./src/lib/server/knowledge-graph-new/knowledge-graph.ts";

const documentId = process.argv[1];
if (!documentId) throw new Error("KG_DOCUMENT_ID is required.");

const chunkLimit = process.env.KG_CHUNK_LIMIT
  ? Number(process.env.KG_CHUNK_LIMIT)
  : undefined;
const output = process.env.KG_OUTPUT ?? "knowledge-graph.json";

const result = await buildKnowledgeGraph({
  providerId: "ollama",
  modelId: "gemma4:12b",
  documentIds: [documentId],
  ...(chunkLimit ? { chunkLimit } : {}),
  onProgress: (progress) => console.error(JSON.stringify(progress)),
});

await writeFile(output, JSON.stringify(result, null, 2));
console.log(`Saved ${result.graph.entities.length} entities and ${result.graph.assertions.length} assertions to ${output}`);
'@
```

## 9. Run the 30-chunk benchmark first

```powershell
$env:KG_CHUNK_LIMIT = "30"
$env:KG_OUTPUT = "knowledge-graph-benchmark.json"

node --import tsx --input-type=module `
  -e $RunKnowledgeGraph `
  $env:KG_DOCUMENT_ID
```

This samples across the document. Review
`knowledge-graph-benchmark.json` before paying the cost of the full run.

The benchmark and full build can discover different corpus schemas, so the full
build may not reuse benchmark extraction results. Repeating the same benchmark
command does resume that benchmark.

## 10. Inspect the benchmark

Open the complete result:

```powershell
notepad .\knowledge-graph-benchmark.json
```

Or print a compact assertion table:

```powershell
$InspectGraph = @'
import { loadKnowledgeGraph } from "./src/lib/server/knowledge-graph-new/knowledge-graph.ts";

const graph = await loadKnowledgeGraph([process.argv[1]]);
console.table(graph.entities);
console.table(graph.assertions.map((assertion) => ({
  subject: assertion.subject,
  relation: assertion.canonicalPredicate,
  object: assertion.object,
  status: assertion.status,
  extractors: assertion.provenance.extractors.join("+"),
  verified: assertion.provenance.verified,
  evidence: assertion.evidence,
})));
'@

node --import tsx --input-type=module `
  -e $InspectGraph `
  $env:KG_DOCUMENT_ID
```

Check especially:

- Whether endpoints are real named or stable technical/historical entities.
- Whether the direction and predicate are meaningful.
- Whether the evidence explicitly supports the assertion.
- Whether generic formatting labels or co-occurrence edges survived.
- How many assertions came from both extractors versus one verified extractor.

## 11. Run the full document

Remove the benchmark limit and change the output:

```powershell
Remove-Item Env:KG_CHUNK_LIMIT -ErrorAction SilentlyContinue
$env:KG_OUTPUT = "knowledge-graph-full.json"

node --import tsx --input-type=module `
  -e $RunKnowledgeGraph `
  $env:KG_DOCUMENT_ID
```

Do not close the PowerShell window while the command is active. The first run
also downloads the GLiNER model from Hugging Face.

## 12. Resume after a failure

Rerun the exact same full command:

```powershell
node --import tsx --input-type=module `
  -e $RunKnowledgeGraph `
  $env:KG_DOCUMENT_ID
```

Successful schema, Gemma, GLiNER, and reconciliation stages are cached in
`app.db`. Keep all of these unchanged while resuming:

- Document content and selected document ID.
- `gemma4:12b`.
- GLiNER model and thresholds.
- Knowledge Graph source code.

Changing those inputs intentionally creates different cache keys.

## 13. Inspect the final graph

The full graph is saved in:

```text
knowledge-graph-full.json
```

Run the `$InspectGraph` command from step 10 again to inspect what was persisted
to `app.db`.

The JSON includes:

- The discovered corpus schema.
- Canonical entities and aliases.
- Directed assertions.
- Exact or derived evidence.
- Document and chunk IDs.
- Dates, negation, and uncertainty.
- Extractor agreement, verification, scores, and offsets.

## Troubleshooting

### `No stored document chunks are available`

The command is running from the wrong directory, `app.db` was not copied, the
document was not ingested, or the selected document ID is wrong. Repeat steps 6
and 7.

### `spawn ... ENOENT`

Python was not found. Verify:

```powershell
Test-Path .\.venv\Scripts\python.exe
```

If using a different environment, set its executable for the current session:

```powershell
$env:KNOWLEDGE_GRAPH_PYTHON = "C:\path\to\python.exe"
```

### GLiNER import or `inference` errors

Reinstall from the pinned requirements file:

```powershell
.\.venv\Scripts\python.exe -m pip install --force-reinstall `
  -r .\src\lib\server\knowledge-graph-new\requirements.txt
```

Do not replace it with the older PyPI-only GLiNER build; that build lacks the
joint relation-extraction API used here.

### Ollama connection errors

Open Ollama from the Windows Start menu, then verify:

```powershell
ollama list
Invoke-RestMethod http://localhost:11434/api/tags
```

### A run fails after substantial progress

Do not delete `app.db` or change model settings. Rerun the identical command.
The cache exists specifically to avoid restarting completed work.

### Out of memory

Close other GPU-heavy programs. GLiNER batch size can be lowered without
changing extraction semantics:

```powershell
$env:KNOWLEDGE_GRAPH_GLINER_BATCH_SIZE = "1"
```

Then rerun. Ollama and GLiNER may use different compute backends and can contend
for GPU memory while both extractors run.
